# Languages, look & feel

SaaSERP ships in **English** and **Arabic** (right-to-left). You can add more languages without touching the screens.

## How it works

- **The English text is the key.** Screens call `t('New booking')`. The active language's dictionary maps that text to its translation. A missing entry falls back to English, so a half-finished language still works.
- **Placeholders** fill in values: `t('Sees own + {n} in team', { n: 3 })`. Translators move `{n}` wherever their grammar needs it.
- **Right-to-left.** In the web app, picking a language sets `<html lang dir>`. The stylesheet uses logical properties (`margin-inline-start`, `text-align: end`, …), so the whole layout mirrors. Charts stay left-to-right so that time still runs left to right. On phones, React Native flips the layout once the app restarts. The app tells the user when that's needed.
- **Numbers and dates** use the language's `intl` locale. Arabic uses `ar-KW-u-nu-latn`, which gives Arabic month names with Western digits (0-9) for amounts. Money and times always follow the **workspace's** currency and time zone.
- **Pick-lists** (event types, sources, lost reasons, …) are company data, not code. Admins translate them under **Settings → Lists**, where each extra language has its own column. The translations are stored in `lookups.translations` (`{"ar": "حفل زفاف"}`).

### Which language a user sees

1. The user's own choice: **Preferences** (web), or **More → Language & appearance** (mobile). It's saved in `users.preferences.locale`, so it follows them to every device.
2. Otherwise, the company default: **Settings → Company → Default language** (`tenants.default_locale`).
3. Otherwise, the browser or phone language, if SaaSERP has it.
4. Otherwise, English.

The sign-in and sign-up pages have a language switch of their own.

## Adding a language (e.g. French)

1. **Web:** copy `apps/web/src/i18n/ar.ts` to `apps/web/src/i18n/fr.ts` and translate the values. Keep every key exactly as it is.
2. Register it in `apps/web/src/i18n/index.ts`:
   ```ts
   import fr from './fr';
   // …
   { code: 'fr', name: 'Français', dir: 'ltr', intl: 'fr-FR', dict: fr },
   ```
3. **Mobile:** do the same with `apps/mobile/src/i18n/ar.ts`. Register it in `apps/mobile/src/i18n/index.ts` with `rtl: false`.
4. Add the language to the **Default language** list in `apps/web/src/pages/Settings.tsx` (the `LANGUAGES` import already feeds it). It also gets a translation column under **Settings → Lists** automatically.
5. Check coverage:
   ```bash
   node scripts/i18n-check.mjs fr     # lists every text not yet translated; exits 1 if any
   ```

The server needs no change. It accepts any `xx` or `xx-YY` language code.

### When you add new screens or text

Wrap visible text in `t('…')` (import `t` from the `i18n` folder). Then run `node scripts/i18n-check.mjs` and add the new keys to every language file. Things that are **not** translated: people's and companies' names, booking names, notes, and anything else that users type in.

The platform operator console (`/platform`) is internal and stays in English.

## Look & feel

Each user picks their own look under **Preferences**. It's stored in `users.preferences` and applied on every device:

| Setting | Values | Where it shows |
|---|---|---|
| Theme | Match my device, Light, Dark | whole app |
| Accent colour | 9 presets, a custom colour, or the company default | buttons, links, active tabs, highlights |
| Density | Comfortable, Compact | tables and cards (web) |
| Text size | 90%–125% | whole app (web) |

- Admins set the **company brand colour** under **Settings → Company**. It's everyone's default accent until a user picks their own.
- Text on accent-coloured buttons switches between black and white automatically, so it stays readable (WCAG contrast).
- **Chart and status colours never change.** Figures and pipeline stages read the same for everyone, whatever theme or accent they choose.
- In the web app, `apps/web/src/appearance.ts` applies the look through CSS variables on `<html>` (`--accent`, `--on-accent`, `--font-scale`, `data-theme`, `data-density`). It caches the look locally so the page doesn't flash on load. In the mobile app, `apps/mobile/src/lib/theme.ts` does the same job.

API: `PATCH /api/me/preferences` with any of `{ locale, theme, accent, density, fontScale }`. Send `null` to go back to the default.
